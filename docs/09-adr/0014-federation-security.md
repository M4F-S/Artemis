# ADR-0014 — Federation security: aggregation, contribution caps, and threat model

## Status
Accepted (Phase 0).

## Context

P6 (privacy) and P16 (self-evolving) commit to federated learning across tenants. ADR-0010 says "Byzantine-robust aggregation." Recent research has established that:

- **Krum** is vulnerable to the "Little Is Enough" attack (Baruch, Baruch, Goldberg, NeurIPS 2019; later refinements 2023–2024) when the attacker knows the variance.
- **FLTrust** is bypassable under bounded-adversary fractions when the attacker can colocate attack vectors with the validator's reference distribution (multiple 2024 attack papers).
- **Median-of-means / trimmed-mean** is geometrically robust but has weaker convergence; the worst-case adversarial damage depends on the trimming fraction relative to the actual adversary fraction.
- No single algorithm is known to be robust against unbounded-magnitude adversarial contributions.

Calling out an algorithm name is not a security argument. We need a concrete, layered scheme with an explicit threat model and stated limits.

## Decision

Federation uses a **multi-layered defence** rather than relying on a single Byzantine-robust algorithm.

### Layer 1 — Per-contributor magnitude bound

- Each tenant contribution is clipped to a fixed ℓ₂ norm before aggregation.
- The clip threshold is published in the manifest; tenants whose unclipped contributions are routinely far above are flagged.
- Effect: bounds the per-round damage any single tenant can cause to the bound × adversary fraction.

### Layer 2 — Coordinate-wise trimmed median

- Aggregator uses coordinate-wise median-of-trimmed-means.
- Trim fraction is set at 30% (assumes ≤ 25% adversarial tenants; budget for 5% noise).
- Geometric robustness even against colluding attackers within the bound.

### Layer 3 — Validator weighting

- A curated set of trusted tenants (initially: design partners; later: paying customers above a tenure threshold) form the validator set.
- Validator updates are weighted 2× in the aggregation.
- Validator membership is rotated quarterly to limit single-tenant influence.
- Validator opts in explicitly; declining is silent and never penalised.

### Layer 4 — Outlier quarantine

- Per-round, contributions whose distance from the post-aggregation result exceeds 4σ are quarantined.
- Quarantined tenants get a notification; if a tenant is quarantined 3 rounds in a row, federation participation is paused and an admin is notified.
- Quarantine evidence is logged in `federation_ledger`.

### Layer 5 — Round-key freshness

- Each aggregation round uses a fresh CKKS key pair generated by the aggregator.
- Round keys are destroyed after aggregation; no replay is possible.
- Forward secrecy: a future compromise of the aggregator does not expose past contributions.

### Layer 6 — Differential-privacy noise

- After median aggregation and clipping, central-DP noise is added to the result.
- Noise magnitude tuned so a single contributor's influence on the output is bounded by a known ε per round.
- Composition over rolling 30-day window tracked per tenant.

## Threat model

Federation is robust against:

- **≤ 25% adversarial tenants** with bounded magnitude attacks.
- **Sybil attacks** up to the per-tenant rate limit (one tenant ID = one contribution per round).
- **Replay attacks** (round-key freshness).
- **Membership inference** with bounded ε.

Federation is NOT robust against:

- **Unbounded magnitude attacks** — aggregator pauses federation when ≥ 5% of contributions are quarantined in a single round.
- **Coordinated attacks above 25% adversary fraction** — by definition; we'd need a different scheme (BFT with > 2/3 honest majority, much higher operational cost).
- **Compromise of the aggregator itself** — out of scope for this ADR; covered by ADR-0015 (signing key management) and ADR-0016 (update channel).

## Pause conditions

The aggregator pauses (skips a round; no model update) if any of:

- ≥ 5% of contributions quarantined as outliers.
- Validator-set disagreement > 2σ.
- Insufficient contributions from validator set (< 5 active validators).
- Active investigation of suspected tenant compromise.

## Consequences

- Per-round aggregation cost rises 2–3× vs. naive averaging.
- Convergence is slightly slower; expect ≥ 2× the rounds to reach the same accuracy as a non-robust scheme.
- Customer messaging must be honest: "robust within bounded adversarial fraction" — not "secure against any attack."
- A pause is a normal, intended outcome; UI must distinguish pauses from outages.

## Verification

- CI invariant: aggregator refuses to publish if any layer's pre-conditions are not met.
- Per-round audit: quarantine rate, validator disagreement, round-key destruction confirmed.
- Annual external audit of the federation pipeline.
