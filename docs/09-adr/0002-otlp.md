# ADR-0002 — OTLP as the on-the-wire telemetry format

## Status
Accepted (Phase 0).

## Context
We need a wire format for sensor → control-plane events that:
- Is dense and fast.
- Allows SIEM integrations without translators.
- Has rich existing tooling.
- Allows future ingestion by third parties.

Candidates: custom protobuf, OpenTelemetry OTLP, ECS (Elastic), CEF, OCSF native.

## Decision
Use **OpenTelemetry OTLP** (gRPC + protobuf) as the wire format. Map alerts to **OCSF** before persistence. Use ECS / CEF / Splunk CIM as outbound translation targets at the SIEM connector level.

## Rationale
- OTLP is a stable, vendor-neutral standard.
- gRPC + protobuf provides compactness and streaming.
- OCSF alignment for alerts gives interoperability across security tooling.
- Splunk, Sentinel, Elastic all ingest OTLP today.

## Consequences
- We commit to the OpenTelemetry attribute conventions where they exist; extend with `artemis.*` namespaces where they don't.
- Schema evolution must respect OTLP's compatibility rules.
